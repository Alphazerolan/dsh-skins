皮肤中心发布 0.4.8，沿用 dsh-web 家族的统一版本号。本版本没有新增皮肤，全部改动都是缺陷修复：补齐独立安装下缺失的 macOS 窗口拖拽守卫，让 furina 不再在 Windows 桌面壳里用整窗画框盖住插画，并把 miku 的会话标题栏横带放回半透明档位。三处缺陷都只在真实壳层上出现，CI 的渲染夹具不覆盖它们。

> **重要变更**：本版本没有需要手工迁移的改动，没有重命名任何已持久化的标识符、线协议字段或 profile 格式。包名 `@linxin666/dsh-client-ui-skin-center` 与安装方式不变，`files` 白名单仍然只内置 `blue-fantasy`。三处修复都是样式层改动，激活中的皮肤刷新页面即生效，不需要重启宿主。

### 修复

- 补上 macOS 窗口拖拽守卫（zhu1090093659/dsh-web#1907）：官方基础样式把每个直接挂在 `body` 下的元素都算成 `-webkit-app-region: no-drag` 区域（它的选择器只放过应用自己的根元素），而 Electron 把可拖拽区算成 union(drag) 减去 union(no-drag)，于是铺满视口的 `body` 子元素把整窗从这个区域里减掉——标题区拖不动窗口，macOS 的双击缩放也不再触发。这条守卫此前只存在于聚合包，独立安装皮肤中心时那一层从不加载，所以缺陷在原版安装里一直可达。现在守卫写在本包自己注入的全局样式表里：`pointer-events: none` 不能豁免一个元素，只有它自己的声明才行，于是六层装饰（`[data-dsh-skin-layer]`）、输入区磨砂跟随层（`[data-dsh-composer-frost]`）与不带 data 钩子的背景纱（`[aria-hidden="true"]`）统一用 `-webkit-app-region: initial !important` 退出这次计算，其中 `!important` 是必须的，官方那条选择器比它更具体。它故意不挂在激活视觉的选择器下：这些层在任何皮肤被选中之前就已挂载，加视觉前缀只会让守卫在缺陷发生的原版安装里失效。`tests/darwin-window-drag.spec.ts` 锁住这四条判定
- furina 0.1.20 在 Windows 桌面壳里让整窗画框盖住插画（#78）：皮肤把 `--dsw-specific-sidebar-fill` 写成固定的 `#f2f5fae6` / `#1d2539e6`（alpha 0.902，不随蒙层滑块变化），Windows 壳把该 token 画在整窗 `*_frame` 元素上——它是会话列的祖先、自成层叠上下文，于是画在宿主 `z-index: -2` 的背景插画之后，美术只剩大约一成可见；网页宿主只在侧栏消费同一个 token，所以网页侧一直正常，而 `background-occlusion` 与 `background-blur` 两个滑块都够不到那个画框。补上与 blue-fantasy（#1803）、maid-atelier 和 cyber-night（#1763）已经带着的同一条声明：只清掉画框自己的背景，盒子与几何仍归宿主；`_frame` 用后缀匹配，既穿过壳层的 CSS-module 哈希，也不会被 `/patches` 前缀管线中和。`tests/furina-frame.spec.ts` 九条断言锁住声明、选择器、只清漆面、它不得改写的 token，以及 Windows 壳夹具下的层叠结果，删掉规则会挂掉其中六条
- miku 0.5.1 的会话标题栏横带在插画上仍是一块实板（#71）：横带不是画在插画上的第一层，皮肤中心还铺了一层 `contributes.backgroundMedia.scrim`（浅色 0.50 / 深色 0.12），合成不透明度是 1 - (1 - scrim)(1 - 横带)，于是用户看到的是浅色 0.94 → 0.86、深色 0.86 → 0.70，等于一块不透明的板。宿主在空会话首屏也渲染这条 header，那里既没有标题也没有标签页，横带 40 CSS px 的下缘就把插画切成了两半。横带回到规则自己的注释声称的那档半透明：浅色 0.239 → 0.078（合成 0.62 → 0.54），深色 0.302 → 0.122（合成 0.39 → 0.23），收口的发丝线不变；`tests/miku-patches.spec.ts` 锁住两条渐变、横带与发丝线的设计语言、横带相对 manifest scrim 允许叠加的上限，以及皮肤中心实际下发的选择器，对着已发布样式表跑有 6/10 条失败

### 其他改动

- 版本推进到 0.4.8，与 dsh-web 家族的统一版本线一致。本仓只发一个包，`package.json` 的 `version` 是唯一的版本声明；构建产物里唯一的变化是 `lib/client.js` 中被编译期常量 `__DSH_PKG_VERSION__` 烘进去的版本串。皮肤自身的 manifest 版本不随家族版本走，本轮没有皮肤升版
- Agent Notes 记录 2026-10-17 的皮肤收件轮：#74（whale-senren）的证据门与美学评审都通过，卡在记录自相矛盾——manifest 以 Senren Banka 的中文标题命名该皮肤，描述却声明不含任何既有作品的元素；#68（model-dorm）仍在 changes requested，新增的两张证据图与改动前逐字节相同。同一轮还把 Windows 画框那条 Note 的触发面扩成实测数据：本仓 61 套皮肤里 58 套定义该 token，其中 48 套 alpha >= 0.5，25 套仍没有画框规则，white-snake 是下一个同类候选

The skin center publishes 0.4.8 on the family's shared version line. There are no new skins this time; every change is a defect fix: the missing macOS window-drag guard is restored for standalone installs, furina no longer covers its artwork with the whole-window frame on the Windows desktop shell, and miku's session-header band returns to the translucent range. All three defects only show up on a real shell, and no rendering fixture in CI covers them.

> **Important change**: there is nothing to migrate by hand in this release. No persisted identifier, wire field or profile format was renamed. The package name `@linxin666/dsh-client-ui-skin-center` and its install path are unchanged, and the `files` whitelist still ships only `blue-fantasy`. All three fixes are stylesheet-level, so a page reload applies them to the active skin without restarting the host.

### Bug Fixes

- The macOS window-drag guard is restored (zhu1090093659/dsh-web#1907): the official base stylesheet resolves every direct `body` child into a `-webkit-app-region: no-drag` region (its selector spares only the app's own root element), and Electron composes the draggable region as union(drag) minus union(no-drag), so a full-viewport body child subtracted the whole window from it - the title area could no longer drag the window, and macOS stopped running its double-click zoom there. The guard existed only in the aggregate package, which a standalone install of the skin center never loads, so the defect stayed reachable there. It now ships in this package's own injected stylesheet: `pointer-events: none` does not exempt an element, only a declaration of its own does, so the six decoration layers (`[data-dsh-skin-layer]`), the composer frost follower (`[data-dsh-composer-frost]`) and the backdrop veil that carries no data hook of its own (`[aria-hidden="true"]`) all opt out of that computation with `-webkit-app-region: initial !important`, where the `!important` is required because the official selector outranks this one. The block is deliberately not scoped under the active-visual heads: those layers mount before any skin is chosen, so a visual prefix would keep the guard inert in the stock install where the defect lives. `tests/darwin-window-drag.spec.ts` pins these four decisions
- furina 0.1.20 covered its artwork with the whole-window frame on the Windows desktop shell (#78): the skin writes `--dsw-specific-sidebar-fill` as a fixed `#f2f5fae6` / `#1d2539e6` (alpha 0.902, not scrim-tracking), and the Windows shell paints that token on its whole-window `*_frame` element - an ancestor of the conversation column and a stacking context of its own - so it painted after the host's `z-index: -2` background illustration and the art read as a washed-out plate with roughly a tenth visible. The web host consumes the same token on the sidebar only, which is why it rendered fine there, and neither the `background-occlusion` nor the `background-blur` slider can reach the frame. It now ships the declaration blue-fantasy (#1803), maid-atelier and cyber-night (#1763) already carry: clear the frame's background and nothing else, so the frame's box stays the host's; the `_frame` suffix match covers the shell's CSS-module hash without being neutralized by the `/patches` prefix pipeline. `tests/furina-frame.spec.ts` pins the declaration, the selector, the paint-only rule, the token it must not neutralize, and the cascade under a Windows-shell fixture in nine assertions, six of which fail when the rule is deleted
- miku 0.5.1's session-header band was still an opaque plate over the artwork (#71): the band is not the first layer painted over the illustration - the skin center lays a `contributes.backgroundMedia.scrim` (light 0.50 / dark 0.12) underneath it - so the composited opacity is 1 - (1 - scrim)(1 - band), which put what the user saw at 0.94 -> 0.86 in light and 0.86 -> 0.70 in dark. The host renders that header on the empty hero screen too, where it holds no title and no tabs, so the band's 40 CSS px lower edge cut the artwork in two. The band is back in the translucent range its own comment claims: light 0.239 -> 0.078 (0.62 -> 0.54 composited), dark 0.302 -> 0.122 (0.39 -> 0.23), with the closing hairline unchanged; `tests/miku-patches.spec.ts` pins both gradients, the band and hairline design language, the opacity the band may add over the manifest scrim, and the selectors the skin center actually serves, failing 6 of its 10 assertions against the shipped stylesheet

### Other Changes

- The version advances to 0.4.8, in step with the dsh-web family's shared version line. This repository publishes one package, so `package.json`'s `version` is the only version declaration in it, and the only change inside the committed build output is the version string baked into `lib/client.js` by the `__DSH_PKG_VERSION__` compile-time constant. A skin's own manifest version does not follow the family line, and no skin was versioned in this round
- Agent Notes record the 2026-10-17 skin intake round: #74 (whale-senren) passes the evidence gate and the aesthetic review but is held on a record that contradicts itself, since the manifest names the skin after the Chinese title of Senren Banka while the description states it contains no element of an existing work; #68 (model-dorm) stays on changes requested, as its two new evidence images are byte-identical to the pre-change ones. The same round turns the Windows-frame note's trigger into measured data: 58 of this repository's 61 skins define that token, 48 of those at alpha >= 0.5, and 25 of the 48 still carry no frame rule, with white-snake the next candidate of the same shape
